# Claude Code

Use this reference when Claude Code is a target host: its reserved names in
Phase 1, and its formats in Mode B. It maps the [team design](../design.md) to
Claude Code files. Formats were checked on 2026-11-11 against the official
[subagents](https://code.claude.com/docs/en/sub-agents.md) and
[memory](https://code.claude.com/docs/en/memory.md) pages with Claude Code
2.1.322. Re-read both pages in every run through their raw `.md` URLs, only
from `code.claude.com/docs/`, and record what changed; a field or path the
current page no longer documents is not written.

## Files and names

| Item | Path |
|---|---|
| Role file | `.claude/agents/<name>.md` in the project root |
| Lead block | Root `AGENTS.md`, between the orchestration markers |
| Import line | `@AGENTS.md` as the first line of an existing root `CLAUDE.md` |

- Claude Code identifies a subagent by its `name` field, not the file name;
  keep both equal. A name must not start with `-`, contain `:`, or exceed 256
  characters.
- **Reserved names:** a project subagent with a built-in's name overrides
  the built-in. On 2026-11-11 the built-ins included `Explore`, `Plan`,
  `general-purpose`, `claude`, `statusline-setup`, and `claude-code-guide`.
  Re-read the built-in list in every run, and avoid those names and their
  lowercase or underscore variants (for example `explore`, `plan`,
  `general_purpose`); rename in Phase 1.
- Project subagents are found by walking up from the working directory to the
  repository root, and the definition closest to the working directory wins.
  Report any same-name file in the root's `.claude/agents/` tree.
- Claude Code watches agent directories that existed when the session
  started. After creating `.claude/agents/` for the first time, tell the user
  to start a new session.

## Role file

Write only these frontmatter fields:

| Field | Value |
|---|---|
| `name` | The role name |
| `description` | The role's description from `docs/agents.md`, as a double-quoted YAML string |
| `tools` | The tools from the capability mapping, comma-separated |
| `model` | The mapped tier, or `inherit` |
| `effort` | The design's effort, when the design sets one; independent of `model` |

```markdown
---
name: api_implementer
description: "Implements changes inside the api component (src/api/). Use when the lead delegates api work with an objective and paths."
tools: Read, Grep, Glob, Edit, Write, Bash
model: sonnet
effort: medium
---

<!-- Generated by the orchestration skill from docs/agents.md. Change docs/agents.md and materialize again. -->

<role instructions from docs/agents.md>
```

- The frontmatter's opening `---` must be the first line. Claude Code skips
  a file without `name` or `description`, with an invalid `name`, or with
  YAML that does not parse, and ignores unknown fields without an error.
  Escape `"` and `\` inside the quoted description.
- The body becomes the subagent's system prompt, so it holds the complete
  role specification: mission, project context, inputs, procedure, output,
  boundaries, and escalation.
- Never write `permissionMode`, `disallowedTools`, `mcpServers`, `hooks`,
  `memory`, `background`, `isolation`, `skills`, `initialPrompt`,
  `omitClaudeMd`, `maxTurns`, `color`, or `experimental`. Subagents inherit
  the session's permission mode.

## Capability mapping

| Class | Tools | Enforcement |
|---|---|---|
| read | `Read, Grep, Glob` | enforced: an allowlist in `tools` withholds every unlisted tool |
| edit | `Edit, Write` | enforced as a capability; the write scope is advisory |
| shell | `Bash` | enforced as a capability; with shell, every write restriction is advisory |
| web | `WebFetch, WebSearch` | enforced as a capability |
| delegate | never written | Subagents without `Agent` in `tools` cannot start subagents |

- A role without `edit` and `shell` cannot change files: record its
  read-only restriction as enforced. With `shell`, record it as advisory.
- Listing `tools` also withholds MCP tools. This version grants no MCP tools:
  a role that needs a server is recorded as pending, for the user to extend
  after reviewing it.
- Re-verify the tool names in the current subagents page; on Windows the
  shell tool may be `PowerShell`.

## Models and effort

| Tier | `model` value as checked on 2026-11-11 |
|---|---|
| deep | `opus` |
| standard | `sonnet` |
| fast | `haiku` |
| inherit | `inherit` |

- Aliases follow the current models; a family alias resolves to the main
  conversation's exact model when it belongs to the same family. Re-verify
  the documented aliases in every run. An organization allowlist can
  substitute a model; the plan says so.
- `effort` accepts `low`, `medium`, `high`, `xhigh`, and `max`, depending on
  the model. Write the design's effort when it sets one, whatever the tier;
  omit the field when the design leaves effort to the session.

## Lead block

- By default, Claude Code reads `AGENTS.md` files as project instructions only
  when no `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` exists in the
  working directory or any directory above it, from version 2.1.277. Versions
  before 2.1.277, a disabled built-in `AGENTS.md` plugin, and some earlier
  sessions documented on the memory page read `CLAUDE.md` files only; the
  project-instructions setting values `claude-md` and `managed-only` also keep
  `AGENTS.md` from loading. Report these conditions; the skill does not read
  the user's settings.
- A root `CLAUDE.md` that is a symlink or hard link to `AGENTS.md`, or that
  already contains an `@AGENTS.md` line, needs no change.
- When the root has a `CLAUDE.md` that does not already import `AGENTS.md`,
  the plan adds `@AGENTS.md` as its first line, with that difference, and
  states that the import brings the whole `AGENTS.md`, not only the block,
  into Claude Code sessions.
- When only `.claude/CLAUDE.md` or `CLAUDE.local.md` exists in the root, or
  the installed version is older than 2.1.277, do not write anything for it:
  report the import line for the user to add. Instruction files above the
  root are outside scope; tell the user that one there also stops `AGENTS.md`
  from loading.
- Subagents also load these instruction files, which is why the lead block
  addresses the lead only.
- Running the lead as a session agent with `claude --agent` or the `agent`
  setting replaces the default system prompt; `orchestration` neither uses
  nor recommends it.

## Validation

`claude plugin validate .claude/agents` (documented from version 2.1.233)
reports only frontmatter that fails to parse; it accepted a missing `name`,
invalid names, unknown fields, and invalid values in a check on 2026-11-11.
Run it when the CLI is installed, and always run a field check that the plan
shows, for example a short `python3 -I` script that reads each file's lines:

- the first line is `---` and a second `---` closes the frontmatter;
- every frontmatter line is `key: value` with a key from the table above,
  each key once;
- `name` equals the file name, matches the design's naming rule, and is not
  reserved;
- `description` is a non-empty double-quoted string;
- `tools` lists only tools from the capability mapping;
- `model` is a re-verified alias or `inherit`, and `effort` is a documented
  level;
- the body contains the generated marker, the role's mission, write scope,
  and boundaries, and is not empty.

Check the installed version with `claude --version` before planning; without
the CLI, record its check as `not run`.

## Starting the team

Report to the user: start a new Claude Code session in the project root and
confirm the startup line that says `AGENTS.md` was loaded, or that `CLAUDE.md`
imports it; the lead follows the block; a role can be requested by name in a
prompt or with an `@agent-<name>` mention, and the `@` typeahead lists the
loaded roles. No Claude Code setting is required for the team.
